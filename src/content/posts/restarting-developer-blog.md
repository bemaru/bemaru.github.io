개발자로 일하면서 많은 문제를 해결했지만, 시간이 지나면 결과만 남고 **왜 그런 판단을 했는지**는 쉽게 사라졌습니다. 이 블로그는 단순한 팁 모음보다, 다음 프로젝트에서도 다시 사용할 수 있는 문제 해결의 맥락을 남기기 위해 다시 시작합니다.

## 무엇을 기록할 것인가

주요 주제는 다음과 같습니다.

- AI Agent의 도구 호출, 오케스트레이션, 평가와 운영
- Python, Go, OpenSearch를 활용한 백엔드와 검색 시스템
- EDR와 탐지 시스템을 개발하며 얻은 Security Engineering 경험
- 개발 환경과 업무 흐름을 개선한 과정

완성된 결과만 보여주기보다 문제, 선택지, 검증 방법, 트레이드오프와 운영 이후의 변화까지 함께 기록하려고 합니다.

## 블로그 구조

사이트 구조는 처음부터 복잡하게 만들지 않았습니다.

- **Writing**: 기술 글과 문제 해결 기록
- **Projects**: 대표 작업을 케이스 스터디 형태로 정리
- **About**: 개발자로서의 관심 분야와 기록 원칙
- **Tags**: 글이 쌓인 뒤 주제별로 탐색하기 위한 분류

검색, 댓글과 방문 분석은 실제 필요가 생긴 뒤 추가합니다. 블로그 인프라보다 콘텐츠가 우선입니다.

## 운영 방식

글은 Markdown으로 작성하고 GitHub에서 버전 관리합니다. Pull Request마다 타입 검사와 정적 빌드를 실행하고, `main` 브랜치에 반영되면 GitHub Pages로 자동 배포됩니다.

게시 날짜는 Git 커밋 날짜와 분리합니다. 예전에 작성한 글을 옮길 때는 원래 날짜를 유지하고, 이후 큰 수정이 있을 때만 수정 날짜를 별도로 표시합니다.

앞으로는 완벽한 글을 한 번에 만들려고 미루기보다, 공개할 가치가 있는 경험을 작은 단위로 꾸준히 정리해 나가겠습니다.
